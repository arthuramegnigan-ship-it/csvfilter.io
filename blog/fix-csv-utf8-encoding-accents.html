How to Fix UTF-8 Encoding and Broken Accents in CSV Files

Troubleshooting · 6 min read

You open a CSV and the names look wrong: Müller shows up as MÃ¼ller, café becomes cafÃ©, and every accented letter has turned into a little cluster of symbols. Nothing is actually broken in your data — it's a character-encoding mismatch, and once you understand it, it's quick to fix.

Why accents break in CSV files

A CSV file is just text, and text has to be saved using an encoding — a system that maps characters to bytes. The modern standard is UTF-8, which can represent every accented and non-Latin character. The problem appears when a file is saved in one encoding but opened as another.

The classic case: a file is saved as UTF-8, but Excel on Windows assumes the older Windows-1252 (ANSI) encoding when it opens it. The accented characters get reinterpreted byte-for-byte, and you get the familiar garble — often called mojibake.

If é turns into Ã©, you're almost always looking at a UTF-8 file being read as Windows-1252.

How to fix it in Excel

Don't double-click the file. Import it and tell Excel the encoding instead:

  1. Open a blank workbook.
  2. Go to Data → From Text/CSV.
  3. Select your file. In the preview dialog, set File Origin to 65001: Unicode (UTF-8).
  4. Confirm the delimiter looks right, then load.

When you save, use CSV UTF-8 (Comma delimited) from the format list — that's the version of CSV that keeps accents intact for the next person who opens it.

How to fix it in Google Sheets

Google Sheets handles UTF-8 well by default. Use File → Import → Upload, and Sheets will usually detect the encoding correctly. When you're done, File → Download → Comma-separated values exports clean UTF-8.

How to fix it in a text editor

For a quick re-save, open the file in an editor that exposes encoding (such as VS Code or Notepad++). In VS Code, the encoding is shown in the bottom bar — click it, choose Reopen with Encoding → UTF-8 to read it correctly, then Save with Encoding → UTF-8 to write it back.

What the byte-order mark (BOM) does

There's one extra trick that makes UTF-8 files "just work" in Excel: a byte-order mark, a tiny invisible marker at the very start of the file that tells Excel "this is UTF-8." A UTF-8 file with a BOM opens with correct accents on a double-click; the same file without one may not.

Good to know. When you export filtered data from CSVFilter.io, the CSV includes a UTF-8 BOM automatically — so accents survive the round trip into Excel without any of the steps above.

Avoid mojibake in the first place

  • When a tool offers it, always choose UTF-8 on export.
  • In Excel, save as CSV UTF-8 rather than plain CSV.
  • Open CSVs through an import dialog where you can set the encoding, instead of double-clicking.
  • If you're just trying to read or filter a file, open it in a browser tool that defaults to UTF-8 — there's nothing to configure.
